# 3A Water Three.js Project Initialization Prompt

## 用途

这份 prompt 用于初始化一个类似 `my-example` 的 Vite + Three.js 第三人称 3D 地形探索项目，并重点测试不同大模型在工程搭建、模块拆分、实时渲染、水体 shader、地形交互和验证闭环方面的能力。

建议将下面的完整 prompt 复制到待测试模型中，在一个空目录里执行。

## Prompt

````text
你是一个资深前端图形工程师和实时渲染工程师。请在当前空目录中从零初始化一个类似 `my-example` 的 Vite + Three.js 第三人称 3D 地形探索项目，用于测试大模型的编程、架构、实时图形和工程验证能力。

重要目标：
这个项目不是普通 demo，而是一个“可继续扩展成 3D 游戏原型”的工程基线。视觉重点是自然地形、第三人称探索、程序化植被，以及接近 3A 游戏观感的水面系统。

请直接实现项目，不要只给说明。

实现高级水体时，可以参考 `river-creator` 的设计思路：优先使用沿地形和河道路径生成的河流网格、水面 shader、流向、岸线融合、浅水/深水颜色、泡沫、高光、Fresnel、程序化波纹和湿岸过渡，而不是简单放置一张平面水面。

一、技术栈

请使用：

- Vite
- 原生 JavaScript ES Modules
- Three.js
- WebGL shader / THREE.ShaderMaterial
- CSS
- 不使用 React、Vue、Angular
- 不使用大型游戏引擎
- 不依赖付费资源
- 不依赖无法访问的外部素材
- 项目必须能通过以下命令运行：

```bash
npm install
npm run dev
npm run build
```

二、最终体验

打开页面后应直接进入一个第三人称 3D 场景：

- 全屏 canvas。
- 玩家位于山地自然环境中。
- WASD 控制玩家移动。
- 鼠标拖拽或 Pointer Lock 控制第三人称相机。
- 相机平滑跟随玩家。
- 玩家移动时 y 坐标贴合地形高度。
- 玩家不能穿过地图边界。
- 左上角有简洁 HUD。
- HUD 显示玩家 x/y/z 坐标。
- HUD 提供至少这些开关：
  - Grass
  - Trees
  - Water Debug
  - Foam Debug
  - Low Quality Water

三、场景要求

请创建一个中大型自然地形场景：

1. 地形
- 使用程序化高度函数生成山地/丘陵地形。
- 地形面积要足够大，让玩家移动时有探索感。
- 地形至少包含：
  - 低地
  - 坡地
  - 高地
  - 河谷
  - 湖边区域
- 地形需要有法线计算，用于光照和坡度判断。
- 提供 `getHeightAt(x, z)`。
- 提供 `getNormalAt(x, z)`。
- 玩家、植被、水体都应复用同一套地形采样逻辑。

2. 光照和氛围
- 使用天空色背景。
- 使用 HemisphereLight 和 DirectionalLight。
- DirectionalLight 需要开启阴影。
- 添加雾效。
- 添加轻量级色调映射和曝光设置。
- 整体视觉应偏自然、清晰、可读，不要做成黑暗糊成一片。

3. 植被和自然物
- 使用 InstancedMesh 生成草、树、石头。
- 植被分布不能完全随机铺满。
- 草更适合低坡度区域。
- 树避开水面和太陡的坡。
- 石头可以出现在河边、坡地、高地。
- 河岸附近应有额外石头或水草，用来打散水陆边界。
- 植被数量要有性能意识，不要创建几千个独立 mesh。

四、重点：接近 3A 感的水体系统

请重点实现一个高级水体系统，而不是简单水面。

水体至少包含：

1. 河流
- 河流必须沿一条弯曲路径生成。
- 使用 CatmullRomCurve3 或类似曲线作为河道中心线。
- 根据中心线采样生成带状 river mesh。
- 不允许只使用一个矩形 Plane 覆盖河道。
- 河流 mesh 至少应有纵向分段和横向分段。
- 横向至少 5 列顶点：
  - 左岸边缘
  - 左浅水
  - 河中央
  - 右浅水
  - 右岸边缘
- `uv.x` 必须表示沿河流方向的距离。
- `uv.y` 必须表示从左岸到右岸的位置。
- 水流动画必须沿 `uv.x` 方向移动，使弯曲河道中的流动方向看起来自然。
- 河流宽度可以沿路径轻微变化。
- 河岸边缘可以有小幅噪声扰动，但不要破坏地形关系。

2. 湖泊或水潭
- 创建至少一个小湖或水潭。
- 湖面应比河流更平静。
- 湖水可以复用水 shader，但流速、波纹、泡沫参数要不同。
- 湖岸也需要浅水、透明、湿岸或泡沫过渡。

3. 水面 Shader

必须使用 `THREE.ShaderMaterial` 实现主要水面效果。

Shader 至少包含以下 uniform：

- `uTime`
- `uCameraPosition`
- `uSunDirection`
- `uShallowColor`
- `uDeepColor`
- `uFoamColor`
- `uReflectionColor`
- `uFlowSpeed`
- `uWaveStrength`
- `uFoamStrength`
- `uDebugMode`

水面 shader 至少实现：

- 多层程序化波纹。
- 法线扰动。
- 浅水和深水颜色混合。
- Fresnel 反射。
- 太阳高光。
- 流动方向动画。
- 岸边透明渐变。
- 岸边泡沫。
- 噪声打散泡沫边界。
- 河中央流速较快，岸边流速较慢。
- 急流区域泡沫更明显。
- 浅水区轻微 caustics 或类似焦散闪光。
- 透明排序设置合理：
  - `transparent: true`
  - `depthWrite: false`
  - 合理设置 `renderOrder`

4. 水面颜色分层

不要使用单一蓝色。

请至少使用这些视觉层：

- 岸边：浅、透明、偏绿或泥色。
- 河中央：更深、更偏蓝绿。
- 急流：更亮、更白。
- 泡沫：接近白色，但不能是纯白硬边。
- 阴影/深水：更暗。
- Fresnel 角度反射：偏天空色。

5. 岸线融合

水陆交界不能生硬。

至少实现以下方案之一，最好同时实现前两项：

方案 A：基于 `uv.y` 的边缘融合
- 使用 `edge = min(vUv.y, 1.0 - vUv.y)` 判断靠岸程度。
- 岸边 alpha 更低。
- 岸边颜色更浅。
- 岸边泡沫更强。
- 泡沫必须使用噪声打散，不允许形成规则白线。

方案 B：湿岸带
- 沿河流两侧生成湿岸 mesh。
- 湿岸带略宽于水面。
- 湿岸材质颜色比干地更暗。
- 湿岸有透明渐变和噪声。
- 湿岸带用于连接干地、湿泥、浅水。

方案 C：深度贴图 shoreline foam
- 如果实现深度贴图，需要正确处理渲染顺序、深度纹理和线性化。
- 这是加分项，不是最低要求。
- 如果实现困难，不要写假代码。优先完成 A 和 B。

6. 泡沫系统

泡沫必须有动机，不能全河平均铺白。

至少出现于：

- 河岸边。
- 河道转弯处。
- 急流段。
- 石头周围。
- 湖泊/河流交汇处或浅滩。

泡沫要求：

- 使用两层噪声：
  - 大泡沫，形状大，速度慢。
  - 小泡沫，细碎，速度快。
- 泡沫沿河流方向流动。
- 泡沫边缘不规则。
- 不要出现连续规则白边。
- Foam Debug 开关应能显示泡沫 mask 或增强泡沫可见度。

7. 石头扰流

请在河中或河岸边放置若干石头。

- 石头可以用程序化几何体生成。
- 石头部分露出水面。
- 石头周围应出现局部白水或泡沫。
- 水 shader 可以通过 uniform 数组接收若干石头位置。
- 不需要无限支持石头数量，限制 8 到 16 个即可。
- 石头附近的泡沫应使用距离场和噪声控制。

8. 急流区域

请在河流某一段实现急流。

急流区域应表现为：

- 流速更快。
- 法线扰动更强。
- 泡沫更多。
- 颜色更浅。
- 高光更碎。
- 但不要变成纯白色条带。

9. 水体调试能力

HUD 中的 Water Debug 和 Foam Debug 应至少能帮助观察：

- 水面边缘透明。
- 泡沫 mask。
- 急流区域。
- 岸边融合。
- 如果实现了 rock foam，能看出石头扰流区域。

Low Quality Water 开关应降低部分效果，例如：

- 减少泡沫层数。
- 降低波纹复杂度。
- 关闭 caustics 或降低高光闪烁。
- 保持项目仍然可运行。

五、玩家和相机

1. 玩家
- 可以用简单胶囊体、圆柱体或低多边形角色代替复杂模型。
- 玩家必须清晰可见。
- 玩家有朝向。
- 移动方向应相对相机方向。
- 玩家移动时应贴合地形高度。
- 玩家在水边移动时不能明显漂浮或陷入地面。

2. 相机
- 第三人称跟随。
- 相机目标应平滑跟随玩家。
- 鼠标控制水平和垂直角度。
- 限制俯仰角，避免翻转。
- 相机距离可以滚轮缩放。
- 相机不要穿到地下。如果不能完整实现碰撞，至少避免低于地形高度。

六、工程结构

请拆成清晰模块，不要把所有代码塞进一个文件。

推荐结构：

```text
index.html
package.json
vite.config.js
src/
  main.js
  style.css
  scene.js
  renderer.js
  input.js
  player.js
  thirdPersonCamera.js
  terrain.js
  water/
    waterSystem.js
    riverGeometry.js
    waterMaterial.js
    foam.js
    wetBanks.js
  vegetation.js
  lighting.js
  math.js
```

最低模块职责：

- `main.js`
  - 初始化 renderer、scene、camera。
  - 创建系统。
  - 主循环。
  - resize。
  - HUD 更新。

- `scene.js`
  - 创建场景对象。
  - 组织 terrain、water、vegetation、lights。

- `terrain.js`
  - 程序化高度。
  - 地形 mesh。
  - 高度采样。
  - 法线采样。
  - 坡度判断。

- `water/waterSystem.js`
  - 创建河流、湖泊、湿岸。
  - 更新水体 uniform。
  - 管理 debug mode。

- `water/riverGeometry.js`
  - 根据曲线生成河流带状 mesh。
  - 生成 uv、world position attribute 或其他 shader 所需属性。
  - 计算河流采样点、切线、侧向。

- `water/waterMaterial.js`
  - 创建 ShaderMaterial。
  - 包含 vertex shader 和 fragment shader。
  - 管理水面 uniforms。

- `water/wetBanks.js`
  - 生成湿岸 mesh。
  - 打散河岸边缘。
  - 创建湿岸材质。

- `vegetation.js`
  - 生成树、草、石头。
  - 使用 InstancedMesh。
  - 根据高度、坡度、水边距离控制分布。

- `player.js`
  - 玩家对象。
  - 移动。
  - 朝向。
  - 地形贴合。

- `thirdPersonCamera.js`
  - 跟随逻辑。
  - 鼠标视角。
  - 距离控制。

- `input.js`
  - 键盘。
  - 鼠标。
  - Pointer Lock 或拖拽状态。

七、代码质量要求

- 保持代码简单、清晰。
- 不要过度抽象。
- 不要创建未要求的战斗、背包、任务、多人系统。
- 不要写无法运行的伪代码。
- Shader 可以适度复杂，但要能构建通过。
- 对水面 shader 的关键逻辑加简短注释。
- 不要依赖外部图片也能运行。
- 如果使用程序化噪声，请直接在 shader 中实现 hash/noise。
- 控制性能，不要让初始场景严重卡顿。
- 使用 InstancedMesh 优化重复物体。
- 避免无意义的大型框架。

八、视觉验收标准

完成后页面应满足：

- 能看到起伏自然的地形。
- 能看到弯曲河流沿地形穿过场景。
- 河水不是静态蓝色平面。
- 河流有明确流动方向。
- 河中央和岸边水色不同。
- 岸边有透明过渡。
- 岸边有不规则泡沫。
- 石头周围有局部扰流泡沫。
- 至少有一段急流。
- 湖面比河流更平静。
- 水体有 Fresnel 角度反射感。
- 阳光下有水面高光或 sparkle。
- 浅水处有轻微焦散或浅色水底感。
- 水陆交界不应像硬切的塑料片。
- 玩家、树、草、石头、水面、地形都能区分。
- WASD 移动正常。
- 相机跟随正常。
- HUD 坐标和开关正常。

九、验证要求

实现后必须执行：

```bash
npm run build
```

如果构建失败，请修复后再次运行，直到通过。

最终回复请包含：

1. 如何运行项目。
2. 构建是否通过。
3. 实现了哪些核心模块。
4. 水体系统具体实现了哪些效果。
5. 哪些效果是低成本近似，哪些可以继续升级。
6. 如果有未完成项，明确说明原因，不要假装完成。

十、加分项

如果时间和复杂度允许，可以添加：

- 瀑布或小落差。
- 瀑布底部水雾粒子。
- 玩家踩进浅水时产生涟漪。
- 河流局部流速 mask。
- 屏幕空间折射。
- Depth Texture shoreline foam。
- 环境反射贴图。
- 水下河床鹅卵石。
- 河边漂浮树叶或小泡泡。
- 移动端/低配水面模式。

但注意：
加分项不能破坏基础功能。优先保证项目可运行、构建通过、水体主效果完整。
````
